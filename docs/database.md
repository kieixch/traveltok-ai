# Database

> Current status: **Phase 2 — domain schema, migrations and seed implemented.**

## Connection

- Provider: PostgreSQL 16 (docker image `pgvector/pgvector:pg16`).
- Prisma ORM v7 with `prisma-client` generator + `@prisma/adapter-pg`.
- Schema: `prisma/schema.prisma` (canonical).
- Migrations: `prisma/migrations/`.
- Client output: `packages/database/src/generated` (gitignored, regenerated by
  `npm run db:generate`).

## Prisma configuration (`prisma.config.ts`)

```ts
export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: { path: "prisma/migrations", seed: "tsx prisma/seed.ts" },
  datasource: { url: env("DATABASE_URL") },
});
```

Environment is loaded explicitly with `dotenv/config` (Prisma v7 does not load
`.env` automatically).

## Driver adapter

Prisma v7 requires a driver adapter at runtime (`packages/database`):

```ts
const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL });
export class PrismaService extends PrismaClient {}
```

The client connects lazily so the API can boot without PostgreSQL; `/health`
surfaces connectivity.

## Commands

```bash
npm run db:generate        # generate client into packages/database/src/generated
npm run db:migrate         # prisma migrate dev (creates/applies migrations)
npm run db:migrate:deploy  # prisma migrate deploy (non-interactive)
npm run db:seed            # prisma db seed → tsx prisma/seed.ts
```

> Note (Prisma v7): `migrate dev`/`db push` no longer run `prisma generate`
> automatically — run `db:generate` after changing the schema.

## Domain schema

Canonical source: `prisma/schema.prisma`. All counts below are defined models;
seed data is separately labeled with `isSeedData = true` so it can be wiped and
regenerated without touching real data.

### Models & key constraints

| Model | Purpose | Uniques / important indexes |
| --- | --- | --- |
| `User` | Auth identity | `email` unique |
| `Project` | Workspace (niche, owner) | index `createdById` |
| `ScrapingJob` | Apify job record (status, counts, errors) | index `projectId`, `status` |
| `Creator` | TikTok creator profile | `externalId` unique |
| `Video` | Scraped video (caption, duration, published) | `externalId` unique; index `creatorId`, `projectId`, `publishedAt`, `(projectId, publishedAt)` |
| `VideoMetric` | Engagement snapshot (never overwritten) | `(videoId, collectedAt)` unique — historical snapshots accumulate |
| `Hashtag` | Normalized hashtag | `normalizedName` unique |
| `VideoHashtag` | Many-to-many video↔hashtag | PK `(videoId, hashtagId)`; index `hashtagId` |
| `ContentAnalysis` | AI video analysis (topic, format, hook, sentiment) | index `videoId`, `topic`, `contentFormat`, `destination` |
| `Trend` | Trend scan result (scores, period) | index `projectId`, `keyword`, `periodStart` |
| `ContentIdea` | AI-generated idea | index `projectId`, `status` |
| `ContentPlan` | Publishing plan (date range) | index `projectId` |
| `ContentPlanItem` | Planned post inside a plan | index `contentPlanId`, `scheduledDate`; `contentIdeaId` nullable `SetNull` |

Notes:

- Metric counts (`views`, `likes`, `comments`, `shares`, `saves`) are `BigInt`
  so aggregation never overflows; the API converts them for JSON responses.
- `VideoMetric` rows are appended snapshots (`@@unique([videoId, collectedAt])`),
  never upserted in place, preserving metric history.
- `isSeedData` exists on every model the seed writes to.

## Seed (`prisma/seed.ts`)

Deterministic (fixed RNG seed) development data so the dashboard can be built
before Apify/OpenAI are configured. All rows are labeled `isSeedData = true`;
re-running `npm run db:seed` wipes only seed rows and regenerates identical data.
